# 休息通知

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

組間休息對機械張力與訓練品質至關重要，但使用者常分心滑手機而錯過時機。系統應該在約定的休息秒數結束時主動通知使用者「該做下一組了」，**即使分頁切到背景、螢幕鎖屏也要準時觸發**。

---

## 使用者可以做什麼？

- 在設定面板**啟用通知權限**（手動觸發 `Notification.requestPermission()`）
- 設定休息秒數（預設 90，預設選項：60 / 90 / 120 / 150 / 180）
- 完成一組後，系統自動排程通知；下一組完成會重設計時
- Android 上跳 heads-up 彈窗 + 震動，iOS 上跳系統通知

---

## 相關實作

| 項目 | 位置 |
|------|------|
| Hook | `src/hooks/useRestNotification.js` |
| Service Worker | `src/sw.js` |
| 觸發源 | `src/App.jsx` 的 `lastCompletedAt`（當日 logs 最晚的 `completedAt`） |
| 權限請求 | `requestNotificationPermission()` (hooks/useRestNotification.js) |
| 通知設定 UI | `src/App.jsx` 設定面板 |

### 流程

```
使用者完成一組
  → App.jsx 算 lastCompletedAt
  → useRestNotification 偵測變化 → postMessage 給 SW
  → SW setTimeout(remaining) → showNotification + vibrate
  → 下一組完成 → cancel + 重排
```

---

## 備註

- **必須走 Service Worker**：主執行緒的 `setTimeout` 在背景頁面會被瀏覽器降頻 / 暫停
- Android 必須帶 `vibrate` 參數才會觸發 heads-up 通知（commit `09339f0`）
- iOS PWA 通知需要 HTTPS + 已加到主畫面
- dev 模式下 SW 行為不完整，驗證請用 `npm run build && npm run preview`
