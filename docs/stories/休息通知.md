# 休息通知

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

組間休息對機械張力與訓練品質至關重要，但使用者常分心滑手機而錯過時機。系統應該在約定的休息秒數結束時主動通知使用者「該做下一組了」，**即使分頁切到背景、螢幕鎖屏也要準時觸發**。

---

## 使用者可以做什麼？

- 在設定面板**啟用通知權限**（手動觸發 `Notification.requestPermission()`）
- 設定休息秒數（預設 90，預設選項：60 / 90 / 120 / 150 / 180）
- 完成一組後，系統自動排程通知；下一組完成會重設計時
- 休息中切去看別天、別週也照樣通知：通知跟著最近一筆完成組所在的那一天，不跟畫面
- Android 上跳 heads-up 彈窗 + 震動，iOS 上跳系統通知
- App 開著時，休息中會在底部 tab 列上方浮出**休息膠囊**：倒數 / 目標、下一組是哪個動作第幾組，點了捲到那一組。超過目標時改成「該做下一組了」並顯示超出多少，組間休息線也同步標「超過」。膠囊只在休息開始 3 小時內顯示，不綁日曆日（跨午夜照樣顯示）

## 相關實作

| 項目 | 位置 |
|------|------|
| Hook | `src/hooks/useRestNotification.js` |
| Service Worker | `src/sw.js` |
| 觸發源 | `src/App.jsx` 的 `restContext`：`getLatestDoneSession(logs)` 找最近一筆完成組（`completedAt` 最晚）所在的週 / 天，再用 `getRestContext` 算那一天的休息型別與起算點（`src/utils/pairRoundState.js`） |
| 權限請求 | `requestNotificationPermission()` (hooks/useRestNotification.js) |
| 通知設定 UI | `src/App.jsx` 設定面板 |
| 畫面上的休息膠囊 | `src/components/training/TrainingView.jsx` 的 `RestPill`（目標秒數用同一個 `restNotificationDelay`） |

### 流程

```
使用者完成一組
  → App.jsx 找最近一筆完成組的週 / 天，算 restContext（type / delay / anchorTs / notifyKey）
  → notifyKey 變了 → useRestNotification cancel 舊通知
  → 切到背景 → 可排程的型別才 postMessage 給 SW
  → SW setTimeout(remaining) → showNotification + vibrate
  → 下一組完成 → cancel + 重排
```

- 最近一筆完成組是以前的課表也沒關係：起算點早就過了，剩餘時間 ≤ 0 不會排程
- 中間組跳過時往後找第一個沒跳過的組，還有組沒做就是組間休息，不會變成「繼續下一個動作」

## 備註

- **必須走 Service Worker**：主執行緒的 `setTimeout` 在背景頁面會被瀏覽器降頻 / 暫停
- Android 必須帶 `vibrate` 參數才會觸發 heads-up 通知（commit `09339f0`）
- iOS PWA 通知需要 HTTPS + 已加到主畫面；沒加到主畫面的 Safari 沒有 `Notification` 物件，hook 會直接不排程
- dev 模式下 SW 行為不完整，驗證請用 `npm run build && npm run preview`
