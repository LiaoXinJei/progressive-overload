# 資料持久化與遷移

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

使用者關掉分頁、重新整理、隔天打開 App 都應該看到一模一樣的狀態：當前週次、當前日次、已完成的組數、所有歷史紀錄、設定偏好。沒有後端的情況下，唯一可靠的儲存方案就是 `localStorage`。隨著功能演進，資料結構必須能向後相容，避免老使用者打開新版資料消失。

---

## 使用者可以做什麼？

- 不需要任何登入 / 註冊
- 所有資料自動儲存於瀏覽器 `localStorage`
- 升級新版時，舊資料自動遷移到新結構
- 可在 header 手動「重設所有資料」（需確認）
- 同時開兩個視窗（瀏覽器分頁 + PWA）時，一邊存檔另一邊會重新載入，舊視窗不會蓋掉新資料
- 存檔讀不了時，原本的內容另存一份備份，從空白資料開始並提示；存不進去（空間滿了）時提示一次，不會白畫面

## 備註

- **變更 localStorage 結構必須升 `schemaVersion` 並加遷移邏輯**
- 寫回採全量序列化（每次 state 變化都寫整份），目前資料量小可接受；跟 storage 現值一樣就不寫，兩個視窗不會互相觸發寫入
- 讀不了的存檔另存在 `rp_focus_pro_data_corrupt_<timestamp>`，要救資料從這裡拿
- 同一瀏覽器同一網域共用儲存，跨瀏覽器 / 跨裝置不會同步
- 若未來要做雲端同步，需重新評估：認證、衝突處理、頻寬
