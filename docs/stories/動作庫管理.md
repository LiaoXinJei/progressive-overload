# 動作庫管理

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

預設菜單覆蓋常見動作，但實際健身房可能缺某些器材、使用者可能因傷或偏好想換動作。每次都改原始碼太麻煩，因此提供 UI 層級的動作庫，讓使用者直接維護自己的動作清單與當前菜單的對應。

---

## 使用者可以做什麼？

- **動作庫管理**：新增、編輯、刪除自訂動作（指定名稱、肌群、類型）。刪除正在當替換的動作會先確認，並一起清掉那些替換設定
- **替換動作**：動作右上角「⋯」→「替換動作」，從 sheet 選另一個動作（不影響預設菜單）；替換過的可以「恢復為原動作」
- **調整組數**：「⋯」→「增加一組 / 減少一組」，覆蓋系統自動分配的組數（分週存）
- **調整順序**：「⋯」→「調整順序」進入編輯模式，動作收成精簡列，按住右側把手拖曳，按「完成」離開。平常不顯示把手，避免健身房裡手指一停就誤拖卡片
- ~~重新命名~~：改名入口已在 `b0a44d2` 拿掉；舊資料裡的 `customExerciseNames` 仍會顯示，替換動作時清掉

### 狀態（在 App.jsx）

| 狀態 | 用途 |
|------|------|
| `exerciseLibrary` | 完整動作庫（預設 + 自訂） |
| `exerciseOverrides` | session 內動作替換對應 |
| `customExerciseNames` | 預設動作改名 |
| `customExercises` | 自訂動作（id 為 `custom_<timestamp>`） |
| `customSets` | 各動作每週的組數覆寫（±1），key 為 `w{週}-{session}-{動作 id}`，只影響那一週 |
| `exerciseOrder` | 拖曳後的順序 |

---

## 備註

- 自訂動作 id 以 `custom_` 前綴避開與預設動作衝突
- 替換動作只影響當前位置，不會同步到其他 session
- 替換後組數照週期演算法算，不套用動作庫的 `defaultSets`，替換選單也不顯示組數；組數 ±1 只影響當週（BUG-14）
- 修改預設菜單常數會與使用者的覆寫疊加，**不會**蓋掉使用者資料
