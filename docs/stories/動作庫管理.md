# 動作庫管理

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

預設菜單覆蓋常見動作，但實際健身房可能缺某些器材、使用者可能因傷或偏好想換動作。每次都改原始碼太麻煩，因此提供 UI 層級的動作庫，讓使用者直接維護自己的動作清單與當前菜單的對應。

---

## 使用者可以做什麼？

- **動作庫管理**：新增、編輯、刪除自訂動作（指定名稱、肌群、類型）
- **替換動作**：在當前 session 把預設動作換成另一個（不影響預設菜單）
- **調整組數**：覆蓋系統自動分配的組數
- **拖曳排序**：用拖曳手勢改變 session 內動作順序，自動捲動已調慢以避免誤觸（commit `8f24795`）
- **重新命名**：把預設動作改成自己慣用的名稱

## 相關實作

| 項目 | 位置 |

| 動作庫管理 UI | `src/components/settings/ExerciseLibraryManager.jsx` |

| 預設動作庫 | `src/constants/workouts.js` (`DEFAULT_EXERCISE_LIBRARY`) |

### 狀態（在 App.jsx）

| 狀態 | 用途 |
|------|------|
| `exerciseLibrary` | 完整動作庫（預設 + 自訂） |
| `exerciseOverrides` | session 內動作替換對應 |
| `customExerciseNames` | 預設動作改名 |
| `customExercises` | 自訂動作（id 為 `custom_<timestamp>`） |
| `customSets` | 各動作組數覆寫 |
| `exerciseOrder` | 拖曳後的順序 |

---

## 備註

- 自訂動作 id 以 `custom_` 前綴避開與預設動作衝突
- 替換動作只影響當前位置，不會同步到其他 session
- 修改預設菜單常數會與使用者的覆寫疊加，**不會**蓋掉使用者資料
