# 訓練紀錄與歷史回填

> **狀態**：已完成（持續維運）

---

## 為什麼需要這個功能？

漸進負荷的關鍵是知道「上次做了多少」。每次重新輸入歷史重量既費時又容易錯。系統要在使用者打開 App 時就能看見上次的重量做為基準，並提供快速微調工具方便往上加重。

---

## 使用者可以做什麼？

- **自動回填**：輸入框的 placeholder 顯示該動作 `history` 的最新 `{ weight, reps }`；點組號把這兩個值填進這組（commit `b0a44d2`）
  - 已完成的組組號不能點，不然會用歷史（可能是後面組的數字）蓋掉這組的紀錄
- **快速微調**：重量欄位旁的 + / − 按鈕，預設步進 2kg（可在設定改）
- **✓ 完成**：每組右側的 ✓ 按下才算完成，同時更新 history、開始休息計時。輸入重量或次數不會自動完成
  - 空白欄位用上次紀錄（就是 placeholder 顯示的值），所以帶入後或照上次做時按一下 ✓ 就好
  - 重量空白、也沒有上次紀錄時當 0 kg（自體重）
  - 次數沒填、上次也沒有次數時 ✓ 不能按
  - 再按一次 ✓ 取消完成，數字保留；已完成的組直接按跳過也一樣。history 照下面「最新一筆」的規則重算
- **history = 最新一筆完成組**：某個動作的 history 是它在所有週、所有 log 裡「最新」那筆完成組的重量 / 次數
  - 「最新」照課表順序比：週 → 天 → 第幾組，同一格才比 `completedAt`。回頭補記舊週的組，完成時間雖然是現在，但它不是最近一次的訓練表現，不會蓋掉後面週的紀錄
  - 只有動到最新那筆（改它的數字、完成後它成為最新、取消它）才改 history；改舊週或同動作前面的組，history 不動
  - 取消最新那筆，history 退回次新的完成組；這個動作一組完成的都不剩，才還原成第一次完成前的值（`historyBefore`）
  - 完成後清空重量或次數，history 保留原值，不會寫成空白
- **重新完成的時間**：取消完成再按 ✓，要不要沿用原本的完成時間看取消的時機
  - 完成後 60 秒內就取消（`MISTAP_UNDO_MS`）：當成誤按，之後真的做完用按下的時間
  - 超過 60 秒才取消：當成事後修正數字，重新完成沿用原本的完成時間，休息計時、訓練時長、超時判斷不會被推到現在
- **時間戳記**：每組記錄 `completedAt`（按 ✓ 的時間），供休息計時、休息通知、訓練總時長使用
- **刪除自訂動作**：垃圾桶按下會先確認，刪除時一起清掉這個動作的替換設定
- **恢復為原動作**：清掉替換設定與組數覆寫，但這個動作有 log 的週保留組數覆寫（同 v5→v6 遷移），按過 +1 做完的組不會被藏起來；沒 log 的週回到週期演算法的預設

### 資料結構

```js
// logs
{ "w1-d0-bp_flat-s0": {
  weight: 100, reps: 10, done: true, completedAt: 1700000000000,
  historyKey: "bp_flat",   // 完成時這組算哪個動作的歷史（替換過就是動作庫 id）
  historyBefore: { weight: 98, reps: 10 },  // 第一次完成前的歷史，取消到一組完成的都不剩時還原用
} }

// 取消完成後（完成超過 60 秒才取消）
{ "w1-d0-bp_flat-s0": { weight: 100, reps: 10, done: false, firstCompletedAt: 1700000000000 } }

// history (v3)
{ "bp_flat": { weight: 100, reps: 10 } }
```

## 備註

- v2 → v3 的遷移：`history[id]` 從單純 `number` 升級為 `{ weight, reps }` 物件，避免次數資訊遺失
- log 的 `historyKey`、`historyBefore`、`firstCompletedAt` 都是選用欄位，沒有 schema 遷移：舊 log 沒有 `historyKey` 時照現在的替換設定推（有替換就用動作庫 id），沒有 `firstCompletedAt` 就用當下時間
- 完成時把 `historyKey` 記在 log 上，之後替換動作再取消完成，還原的是原動作的歷史，不會寫進新動作
- `historyBefore` 沿用同動作其他完成組記的值，取消順序不同也不會還原成打錯、後來取消的那組數字
- 重量步進在設定面板可改（`weightIncrement`，預設 2）
- 若 history 無紀錄，輸入欄位保持空白
- f3a0c9b 曾拿掉完成按鈕改成「打次數就完成」，造成 history 只存到第一位數、自體重記不了等問題（BUG-03、04、11、19），已改回 ✓ 按鈕（openspec `set-complete-button`）
